# AI 使用与验证记录

> 按时间顺序记录：关键需求和决策、AI 产出中被否决或修正的部分、验证方式、发现的 AI 错误。

## 2026-10-17 · M0 数据探测

**需求和决策**
- 先探测再设计：不凭记忆假设 iFinD 有哪些接口，先调用 `tools/list` 拿到 8 个服务共 40 个工具，再对每类数据真实调用一次（共 57 次）。
- 时间预算从 48h 改为 **24h**（Ray 决定）。
- 扶摇未接入，Ray 决定先测 iFinD、扶摇之后补测。

**发现的数据源问题（不是 AI 的错误，但会让 AI 犯错）**
- 自然语言取数会漂移：同一意图换个问法结果不同（s04/s16、s07/s17、g08/g09）→ 决定用固定模板加列名校验。
- 海外财年标签偏 6 个月：用 SEC EDGAR XBRL 交叉验证 Coherent 的 6 个数值，全部一致，但期间标签不是真实期末 → 写进财年映射和测试。
- 429 被包在 `ok: true` 里：如果只看 ok 字段，会把限频错误当成数据。

**发现的 AI 错误**
- **AI 自己编了数字**：写 `data_probe.md` 的 SEC 对照表时，AI（Claude）从四舍五入后的“亿”值反推出 4,280,680,000、1,581,380,000、3,267,010,000，没有用 SEC 原值（实际是 4,280,679,000、1,581,378,000、3,267,007,000）。
  - 发现方式：写完后回查 `sec_cohr_revenue.json`，逐个打印原值对比。
  - 修复：表格改成原值，补上 accn 编号和来源 URL。
  - 教训：文档里的数字也必须从数据文件里程序化取出，不能由 AI 手抄或“还原”。M1 起报告和页面上的数字一律由 build 脚本生成，并由数字溯源测试兜底。

## 2026-10-17 · M1 采集与解析

**完成了什么**
- `pipeline/ifind.py`：iFinD 客户端（串行限频、识别包在 ok 里的 429、退避重试、请求哈希缓存、调用元数据写入 `api_calls.jsonl`）。
- `pipeline/tables.py` / `fiscal.py`：Markdown 表格解析、数值规范化、财年标签映射到真实区间、单季度推导、TTM。
- `pipeline/ingest.py`：26 家 A 股 + 12 家海外 + 3 个 EDB 指标，共 166 次调用全部 ok，6589 条记录。每条记录都带 `call_id + 列名 + 行号`。
- `pipeline/sec.py` / `checks.py`：SEC EDGAR 第二来源和确定性校验。
- 测试：49 个单测全部通过（解析、财年映射、客户端异常、采集重试、校验逻辑）。

**校验结果（`data/staging/checks.json`，代码生成）**

| 校验 | 结果 |
|---|---|
| A 股单季度累加 = 累计值 | 156 pass |
| 分产品收入合计 ≈ 营收（±0.5%） | 46 pass / 3 warn（都是只返回前 5 项导致合计偏小） |
| 分地区收入合计 ≈ 营收 | 45 pass / 3 warn（同上） |
| 海外营收 iFinD vs SEC 同区间 | 88 pass / 3 skipped（Lumentum FY26 季度数据在 SEC 该标签下缺失） |
| 云厂商 Capex iFinD vs SEC | 24 pass / **2 fail** |

**被否决或修正的 AI 方案**
1. **季度模板（AI 初版）**：一个问句同时查单季度营收、单季度毛利率、单季度净利润，结果 26 家公司全部没有日期列，季度值为空。逐个指标试验后发现，只要包含“单季度销售毛利率”，服务端就不再展开报告期。
   - 修正：逐指标查询，改查“单季度营业成本”，毛利率由代码按 1 − 成本/营收计算。核对：中际旭创 2026H1 推导值 46.25%，iFinD 给出 46.2522%。
   - 同时加了**列名校验**：缺少报告期的记录不入库；批量查询有缺失时逐家重试，仍然缺失的写入 `ingest_report.missing`。
2. **会计年结日**被通用数值解析器转成 630.0，导致财年映射报错（月份变成 63）。修正为还原成 4 位 MMDD 字符串。
3. AAOI 的英文名在 iFinD 里查不到，配置里加了 `ifind_name: 应用光电`。

**发现的数据源问题**
- 云厂商 Capex 有 2 个季度，iFinD 与 SEC 不一致：
  - Meta 2025Q3：iFinD 19,582,000,000 vs SEC 按 YTD 差分 18,829,000,000。
  - Microsoft FY25Q4：iFinD 18,822,000,000 vs SEC 17,079,000,000。
  - 而且 iFinD 自己的四个季度加起来和 SEC 10-K 的全年值对不上（代码验证）：Meta 2025 年 iFinD 四季度合计 70,444,000,000 vs 10-K 69,691,000,000；Microsoft FY2025 iFinD 合计 66,294,000,000 vs 10-K 64,551,000,000。
  - 处理：写入 `conflicts.json`，以 SEC 原始披露为准，iFinD 值保留展示。这两条将作为“两源数字冲突”测试的真实样本。
- 剑桥科技、胜宏科技、工业富联的半年报分产品数据，以及这三家加上海贝岭的半年报分地区数据，逐家重试后仍然没有 → 页面标“iFinD 未收录半年报分部”。
- 12 个海外公司的 CIK 用 SEC 官方 ticker 表校验，全部一致（CIK 是 AI 凭记忆写进配置的，不信任，所以用程序核验）。

## 2026-10-17 · M2 证据抽取与可信度分级

**完成了什么**
- `pipeline/evidence.py`：83 次 iFinD 调用，得到 661 条证据（公告 323、资讯 113、iFinD 概念解析 225）。CPO 概念按市值切 5 片，225 只成分股全部拿到；剔除 28 条属于其他公司的证据。
- `pipeline/extract.py`：DeepSeek 抽取引文。564 条含概念关键词的证据送入 LLM，得到 1074 条引文；被拒 15 条，其中 **5 条引文在原文里找不到**，被逐字校验拦下，例如“紫光股份光模块布局：800G CPO已量产商用”，这句只出现在标题里，正文没有。
- `pipeline/grade.py` / `attribution.py` / `m2.py`：规则裁定等级，按分产品收入归属环节；CPO 225 只成分股全量分级。
- 测试 75 个，全部通过。

**结果（代码生成：`concept_links.json`、`cpo_all_grades.json`、`extractor_comparison.json`）**
- 26 家全集，光互联：A 10 / B 7 / C 7 / D 1 / E 1；CPO：B 4 / C 7 / D 7 / E 8。
- CPO 概念 225 只成分股：B 4 / C 10 / D 18 / E 193。
- 规则按句抽取 vs LLM 抽取 + 规则裁定：有 14 处等级不同，**全部是往下调**。规则按句抽取的典型错误是主语错配：把行业新闻里别家公司的量产（“英伟达 CPO 交换机量产”“新易盛……掌握 CPO 工艺”）算到了本公司头上。LLM 判断了“这句话说的是不是这家公司本身”。

**模型选型（同一批 8 条证据实测）**
- `deepseek-v4-pro`：推理模型，max_tokens=1200 时 6/8 条被思考过程占满、正文为空。调高上限后，8 条用了 246 秒、completion 24,794 token，还有 1 条自造了不在枚举里的概念。
- `deepseek-flash`：8 条用了 77 秒、completion 10,703 token，引文全部通过校验；有 1 条噪声（把“原材料包括…”判成量产），被规则层过滤。
- 决定：用 flash。被截断的响应不缓存、单独报错。

**被否决或修正的 AI 方案**
1. AI 默认写的模型名 `deepseek-chat` 在 `/models` 里不存在（实际只有 deepseek-flash、deepseek-v4-pro）。改为先调接口确认再选。
2. LLM 缓存键最初只用了 evidence_id，改提示词或公司名后仍会命中旧结果。改为对完整提示词做哈希。同时发现约 200 家全集外的 CPO 成分股，传给 LLM 的“公司”字段是股票代码，修正为公司名后重跑。
3. 规则 bug，都是写测试或逐条看结果时发现的（每条都补了回归测试）：
   - “小批量交付”被“批量交付”命中，误判为量产。**AI 最初写的测试期望值也是错的**，跟着代码一起错。
   - 投资者提问（“请问公司CPO…量产进度如何？”）被当成公司表述。
   - “政策……不涉及对公司业务产生影响”被当成否认业务，把天孚通信的 A 误降为 B。
   - iFinD 日期标签“20260630”和 ISO 日期“2026-08-01”直接做字符串比较，冲突判断出错。
   - 招股书里“自 CPO 解决方案产生收入 2.0 百万元”这类文字收入表述没被识别。
   - 将来时被算成进展：“预计 2027 年有批量订单”、“量产进度取决于客户需求”。
   - 同句里别的产品的阶段词串到概念上：“800G 交换机出货量增长……CPO 样机开始出货”。改为分句级识别。
4. 环节归属的文本佐证最初太松：只要有任意一条量产引文，就给所有环节背书，结果剑桥科技的“无线网络设备”被归进了交换机。改为引文必须出现该环节自己的产品词。
5. 源杰科技的“数据中心类产品”最初被直接写进了光芯片的通用词表，会误伤其他公司。改为带理由的单公司映射（依据 iFinD 主营业务字段“光芯片的研发、设计、生产与销售”）。

**新增的设计原则（已写进 proposal）**
- **LLM 只能让结论更保守**：规则阶段和 LLM 建议阶段不一致时，按更保守的一方展示，并标待复核。
- **结构化收入优先**：A 级（分产品收入）不会因为文本否认而降级，只标冲突、待复核。
- 规则回退抽取（无 LLM）得出的等级一律标待复核。
